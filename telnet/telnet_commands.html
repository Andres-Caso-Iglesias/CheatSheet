Comandos Telnet

Referencia interactiva de comandos Telnet

Conexión básica (Telnet)
telnet <host> <puerto>Para qué sirve: Abre una conexión TCP al puerto especificado. Si el puerto está abierto, la pantalla se queda en blanco o muestra un banner del servicio. Si falla, dice "Connection refused" o timeout.
telnet 192.168.1.1 80 · telnet example.com 443
telnet <host>Para qué sirve: Conecta al puerto 23 (Telnet por defecto). La mayoría de servidores modernos rechazan esto porque Telnet es inseguro (texto plano).
telnet 192.168.1.1 → puerto 23 automático
telnet -l <usuario> <host>Para qué sirve: Especifica el nombre de usuario para login automático al conectarse. Envía el comando USER al servidor Telnet antes de pedir contraseña.
telnet -l admin 192.168.1.1
open <host> <puerto>Para qué sirve: Comando interno de la consola Telnet para abrir una conexión sin salir del cliente. Útil para probar múltiples hosts/port sin reiniciar.
telnet → open 10.0.0.1 22
closePara qué sirve: Cierra la conexión Telnet activa pero mantiene el cliente abierto. Puedes volver a conectar con open sin salir de la consola.
close → vuelve al prompt telnet>
quit / exitPara qué sirve: Cierra la conexión y sale del cliente Telnet completamente. Vuelves al prompt del sistema.
quit · exit alias
Modo escape y comandos internos
Ctrl + ]Para qué sirve: Entra al modo de escape de Telnet. Cambia el prompt a telnet> donde puedes ejecutar comandos internos sin cerrar la conexión. Esencial para debug y control.
telnet> prompt de escape · ? ayuda
statusPara qué sirve: Muestra el estado actual de la conexión: host, puerto, estado (Connected/Closed), opciones negociadas y modo de terminal.
status en prompt telnet>
send <secuencia>Para qué sirve: Envía secuencias de control especiales al servidor remoto. Útil para enviar break, IP (Interrupt Process), AO (Abort Output), etc.
send ip interrupt · send ao abort output · send ec erase character
set / unset <opción>Para qué sirve: Configura opciones del cliente Telnet: echo, crlf, binary, skip. Modifica cómo se procesa la entrada/salida localmente.
set echo eco local · set crlf convierte LF a CRLF
toggle <opción>Para qué sirve: Alterna una opción entre on/off. Más rápido que set/unset. Opciones comunes: echo, crlf, binary, skip, crlfmod.
toggle echo cambia estado · toggle crlf
display <opción>Para qué sirve: Muestra el valor actual de una opción del cliente. Útil para verificar configuración antes de debuggear problemas de terminal.
display echo · display crlf · display all
Modo debug y logging (Telnet)
telnet -d <host> <puerto>Para qué sirve: Inicia Telnet con debug activado desde el arranque. Muestra toda la negociación de opciones Telnet (WILL, WONT, DO, DONT) y datos hex.
-d debug mode · muestra negociación de opciones
toggle optionsPara qué sirve: Activa/desactiva la visualización de la negociación de opciones Telnet en tiempo real. Útil dentro de la sesión para ver WILL/WONT/DO/DONT.
telnet> toggle options muestra opciones negociadas
toggle tracePara qué sirve: Muestra los datos que se envían y reciben en formato hexadecimal. Útil para analizar el tráfico de la conexión y ver caracteres de control.
telnet> toggle trace hex dump del tráfico
toggle prettydumpPara qué sirve: Similar a trace pero con formato más legible. Muestra los datos ASCII junto al hex. Útil para ver qué caracteres se envían realmente.
telnet> toggle prettydump hex + ASCII
log <archivo>Para qué sirve: Guarda toda la sesión (entrada y salida) en un archivo de texto. Útil para documentar troubleshooting o analizar interacciones posteriores.
telnet> log session.log guarda en archivo
zPara qué sirve: Suspende la sesión Telnet y vuelve al shell del sistema. La conexión se mantiene abierta. Vuelve con el comando fg (foreground).
telnet> z suspende · fg reanuda
Opciones del protocolo Telnet
WILL / WONTPara qué sirve: El servidor anuncia que quiere (WILL) o no quiere (WONT) usar una opción. El cliente responde con DO (acepta) o DONT (rechaza). Parte de la negociación RFC 854.
WILL ECHO servidor quiere hacer echo
DO / DONTPara qué sirve: El cliente pide (DO) o rechaza (DONT) que el servidor use una opción. El servidor responde con WILL (acepta) o WONT (rechaza).
DO ECHO cliente pide echo al servidor
SB / SE (Subnegotiation)Para qué sirve: Inicio (SB) y fin (SE) de subnegociación. Permite negociar parámetros específicos de una opción como tamaño de terminal, velocidad o tipo de terminal.
SB TERMINAL-TYPE ... SE negocia tipo terminal
IAC (Interpret As Command)Para qué sirve: Byte 255 (0xFF) que indica que el siguiente byte es un comando Telnet, no datos. Si quieres enviar 0xFF como dato, se envía como IAC IAC.
0xFF byte IAC · IAC IAC FF literal
Testing de puertos comunes con Telnet
telnet <host> 80Para qué sirve: Verifica si un servidor web HTTP está escuchando. Si conecta, puedes enviar comandos HTTP manuales: GET / HTTP/1.1 + Host: + doble Enter.
GET / HTTP/1.1 · Host: ejemplo.com · Enter x2
telnet <host> 25Para qué sirve: Prueba conectividad SMTP. Si conecta, el servidor muestra su banner. Puedes enviar comandos SMTP manuales: EHLO, MAIL FROM, RCPT TO.
EHLO test.com · MAIL FROM: test@test.com
telnet <host> 110Para qué sirve: Verifica servidor POP3. Si conecta, muestra +OK banner. Comandos: USER, PASS, LIST, RETR, QUIT. Útil para debug de correo entrante.
USER admin · PASS password · LIST
telnet <host> 143Para qué sirve: Verifica servidor IMAP. Si conecta, muestra * OK banner. Comandos: a LOGIN, a LIST, a SELECT INBOX, a LOGOUT.
a LOGIN user pass · a LIST "" "*"
telnet <host> 21Para qué sirve: Prueba servidor FTP. Si conecta, muestra banner 220. Comandos: USER, PASS, LIST, PWD, CWD, QUIT. Útil para verificar FTP sin cliente.
USER anonymous · PASS guest@ · LIST
telnet <host> 53Para qué sirve: Verifica si DNS está escuchando en TCP (no UDP). La mayoría de consultas DNS usan UDP, pero las transferencias de zona (AXFR) usan TCP.
telnet dns-server 53 prueba TCP DNS
telnet <host> 3306Para qué sirve: Verifica si MySQL está escuchando y accesible desde tu red. Si conecta, muestra un banner con la versión. Si no, firewall o bind-address.
telnet db-server 3306 prueba MySQL
Connection refused vs TimeoutPara qué sirve: "Connection refused" = el host existe pero nadie escucha en ese puerto. "Timeout" = el host no responde (firewall bloquea, host caído, routing roto). Diagnóstico rápido de red.
refused puerto cerrado · timeout firewall/caído
Interacción manual con protocolos
GET / HTTP/1.1 + Host: + Enter x2Para qué sirve: Envía una petición HTTP GET manual via Telnet. Debes presionar Enter dos veces al final (línea vacía requerida por HTTP). Devuelve headers + body.
GET / HTTP/1.1 → Host: target → Enter x2
HEAD / HTTP/1.1 + Host: + Enter x2Para qué sirve: Igual que GET pero solo devuelve headers, sin body. Útil para verificar status code, Server, Content-Type, etc. sin descargar contenido.
HEAD / HTTP/1.1 → headers solo
EHLO dominio.comPara qué sirve: Comando SMTP extendido (ESMTP). El servidor responde con sus capacidades: SIZE, 8BITMIME, STARTTLS, AUTH. Útil para verificar si el servidor soporta TLS o autenticación.
EHLO test.com → lista capacidades
VRFY usuarioPara qué sirve: Verifica si un usuario existe en el servidor SMTP. Muchos servidores lo deshabilitan por seguridad (evita enumeración de emails). Si responde 250, el usuario existe.
VRFY root → 250 o 550
HELPPara qué sirve: Comando genérico disponible en SMTP, FTP y otros protocolos. Devuelve la lista de comandos soportados por el servidor. Útil para descubrir funcionalidades ocultas.
HELP en SMTP/FTP → lista comandos
QUITPara qué sirve: Cierra la conexión de forma limpia en la mayoría de protocolos (SMTP, FTP, POP3, IMAP). El servidor responde con un mensaje de despedida antes de cerrar.
QUIT → 221 Bye (SMTP) · 221 Goodbye (FTP)
